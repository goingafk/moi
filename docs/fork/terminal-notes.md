# Phase 4 terminal verification notes

- Installed Bun 1.4.2 supports `Bun.spawn(..., { terminal: { cols, rows, data } })`. A PTY round-trip test writes to `process.terminal`, receives bytes through `data(terminal, chunk)`, and resizes through `process.terminal.resize`. The browser attaches to a named tmux session rather than owning the shell process. [Bun child-process documentation](https://bun.com/docs/runtime/child-process).
- Local Codex CLI 0.153.4 reports `codex login --device-auth` in `codex login --help`. Local Claude CLI reports `claude auth login` in `claude auth login --help`, but no device-code flag. The terminal presents these commands for the user to review and send; it does not parse an undocumented login URL/code protocol.
- `tmux` is a runtime prerequisite. The terminal uses a dedicated `tmux -L moi` socket and a UUID-named session per terminal. Closing the browser socket kills only its tmux attachment, not the session. Metadata is stored per moi installation in `DATA_DIR/terminals.json`; no workspace-shared state is added.
- Terminal HTTP and WebSocket routes are both inside the existing auth gate and additionally refuse `auth: off`. The remote shell therefore exists only for an authenticated direct-tailnet device or Tailscale Serve user. The shell runs as the moi service OS user, which must not be root.
- The current Mac test host has no tmux. Native PTY and auth tests run locally; a real tmux reattach test is present but skips until tmux is installed. Live MacBook/phone-to-LXC login and disconnect/reconnect remain deployment acceptance checks.
