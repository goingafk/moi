# Ollama discovery and Claude Code integration

Verified against Ollama's current [list models](https://docs.ollama.com/api/tags), [show model details](https://docs.ollama.com/api-reference/show-model-details), and [running models](https://docs.ollama.com/api/ps) references on 2026-09-25. `GET /api/tags` returns `models[]` with `name`/`model`; `GET /api/ps` returns the loaded subset in the same shape; `POST /api/show` accepts `{ "model": "..." }` and returns `capabilities[]`. Tool-capable models advertise `"tools"`. The discovery code calls `/api/show` per model rather than trusting `/api/tags` capabilities, which may be absent or incomplete. A failed detail request leaves the model visible but not selectable for agentic use.

Ollama's [Claude Code integration](https://docs.ollama.com/integrations/claude-code) specifies `ANTHROPIC_AUTH_TOKEN=ollama`, `ANTHROPIC_API_KEY=""`, `ANTHROPIC_BASE_URL=<server origin>`, and `claude --model <Ollama model>`. The integration supports tool calls with compatible models. A live Claude CLI / Ollama run is still needed to validate the complete moi harness path on the owner's server.

Owner-server probe from the MacBook on 2026-09-25: `http://100.125.20.45:11434/api/tags` returned `qwen3.8:27b` (exact name, with a colon) and `gemma4:26b`; both advertised `tools` in tags. `POST /api/show` for `qwen3.8:27b` also returned `capabilities` including `tools`. `GET /api/ps` returned no loaded models, so both should initially display as cold. Connectivity from the moi LXC, rather than the MacBook, still needs verification.

The installed Claude Code CLI is 2.1.282. Its `--help` documents `--strict-mcp-config` as ignoring all MCP sources except explicitly passed servers, and `--setting-sources project` as the project-only settings source. The installed Agent SDK's `Options` type exposes the corresponding `strictMcpConfig`, `mcpServers`, and `settingSources` fields. Moi uses those for Ollama sessions, keeping project skills available while defaulting to zero MCP servers; `localMcpServers` in app settings allow-lists names from the workspace's `.mcp.json`. Normal Claude sessions keep user and project settings without strict MCP filtering.

Live compatibility check from the MacBook: Claude Code 2.1.282, with `ANTHROPIC_AUTH_TOKEN=ollama`, an empty `ANTHROPIC_API_KEY`, the Tailscale Ollama URL, `--strict-mcp-config`, `--setting-sources project`, and no session persistence, returned `READY` from `qwen3.8:27b` in about 12 seconds. A second structured-output run showed an actual `Bash` tool call for `pwd` and a successful tool result of `/private/tmp`; its init frame reported `mcp_servers: []`. It warned that this custom model is absent from its built-in catalog and assumes a 200k-token context window; it also said claude.ai connectors were disabled by the alternate auth source. It did not hang fetching cloud MCP servers. The full moi UI path and LXC-to-Ollama connectivity still need a live owner-LXC test.
